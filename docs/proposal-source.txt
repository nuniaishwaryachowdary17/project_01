3. Overview
The story
A clockmaker has disappeared and left the vault in his workshop locked. The player has to find out what 
happened by searching three rooms: the Study, the Clock Tower and the Archive. Each room hides clues.
Put together, the clues reveal a four-digit code, and entering that code opens the vault.
Why we picked this track
When we first talked about ideas, the escape room kept coming back. A puzzle game is the kind of thing 
people normally build with scripts, and that is exactly why we want to try it without them. Taking 
JavaScript away forces us to understand what CSS can really do: selectors, sibling combinators, pseudo￾The Clockmaker's Vault | CSC 4370/6370 | Page 1
classes, and layout. We have to use those tools to hide content, reveal it, remember what the player has
found, and move the player between rooms. Those are the skills this course is testing, and if it works, 
the finished game is something we would be proud to show in a portfolio.
How a CSS-only game works
Everything the player does is driven by the state of an HTML element, and CSS reacts to that state. We 
will use four techniques:
• :hover and :focus-visible. These respond to the mouse and the keyboard. They handle button 
feedback, card lifts and visible focus rings.
• :checked on radio buttons and checkboxes. A hidden input sits in front of the content it controls. 
When the player clicks its label, CSS uses the sibling selectors (+ and ~) to show or hide other 
elements. Room tabs, clue filters and code dials all work this way.
• :target. A link points to an element id (for example #open). When the player clicks it, the browser 
marks that element as the target and CSS styles it. We use this for the vault door and the wrong￾code panel.
• details and summary. This is a native HTML disclosure widget that opens and closes without any 
script. We may use it for the Apprentice hint cards.
Who it is for
We are building it for classmates and casual puzzle players who want a five to ten minute break. A first￾time visitor should not need instructions to get started. They land on the briefing, see where to go next, 
and can check their progress at any point.
A limit we planned around
CSS cannot remember anything once the player leaves a page, because it has no storage. So each page 
keeps its own copy of the player's progress. For example, the Clue Board has its own set of checkboxes 
where the player ticks the clues they have found, and the filters read those ticks. We chose this on 
purpose instead of faking shared progress, and we will explain the reasoning in the presentation.

5. Functionality
Screen-to-screen transitions
• Home to Rooms: the "Enter the Vault" button rises a few pixels on hover, and the rooms page 
fades in with a short keyframe when it loads.
• Room to room: changing tabs crossfades the room panel using opacity and transform on the 
sibling of the checked radio button.
• Rooms to Clue Board: every room has a "View all clues" link, so players can review their evidence 
and come back to the room they were in.
• Clue Board to Final Unlock: a pulsing "Ready to unlock" badge at the bottom of the board leads 
the player to the last page.
• Wrong code: the player never reaches a dead end. A wrong combination shows the retry panel, 
which shakes briefly and offers a hint link. We explain how this works in the Final Unlock section 
below.
How the Final Unlock page works
Each of the four dials is a group of ten radio buttons (digits 0 to 9) that all sit in the same parent, so CSS 
can see them as siblings. A long selector chain checks whether the right digit is selected in all four dials 
at once. When it is, the page hides the "Try this code" link that points to #retry and shows a different 
link that points to #open. Clicking whichever link is visible changes the target. #open plays the vault 
animation, and #retry shakes the panel and shows a hint. Honestly, this is the part we expect to be 
hardest. Aishwarya will prototype it first, before the other pages are built, so that any surprise shows up 
early and not in the last week.
Transitions
• Nav links: an underline that grows out from the left using transform: scaleX() over 200ms.
The Clockmaker's Vault | CSC 4370/6370 | Page 4
• Buttons: background-color and transform transitions on hover, a slight press on :active, and a 
strong outline on :focus-visible.
• Filter chips and room tabs: opacity and visibility transitions, so cards fade out instead of vanishing 
in a single frame.
• Shared timing: durations and easing live in CSS custom properties (--speed-fast, --speed-base, --
ease-out), so all motion follows the same rhythm and can be tuned from one place.
Transformations
• Clue cards flip with rotateY(180deg). The parent has perspective set, and both faces use backface￾visibility: hidden so the back never shows through.
• Puzzle cards rise with translateY(-4px) and pick up a deeper shadow on hover and focus.
• Vault dials turn with rotate() when selected, and the door opens on a 3D rotateY that pivots from 
its hinge side using transform-origin.
Animations (@keyframes)
• gear-spin: a slow, endless gear rotation in the home page hero.
• clue-pulse: a gentle glow on newly revealed clues and on the "Ready to unlock" badge.
• vault-open: a chained sequence in which the dials lock, the handle turns, and the door swings 
wide.
• panel-shake: a quick shake on a wrong code, kept under 400ms so it reads as feedback and does 
not get annoying.
• Reduced motion: every animation has a prefers-reduced-motion fallback that swaps the 
movement for a simple fade or a still state.
6. Bonus Features (Graduate)
Both features are HTML and CSS simulations. Neither one calls a real AI service, and our README will say
so clearly. Each is part of the main game flow instead of sitting on a separate page.
Feature 1: AI Assistant Panel ("The Apprentice")
• Simulated AI concept: an intent-based conversational assistant. The player picks an intent card, 
such as "I'm stuck in this room" or "What does this symbol mean?", and a matching response card 
opens through :target or details and summary.
• How it behaves: hints come in tiers. The first reply gives a small push, and the second says more, 
so players can ask for exactly as much help as they want.
• Where it lives: on the Rooms page below the puzzle cards. The hint link on the Final Unlock page 
jumps straight to it.
• Original design decision: the replies are written in the voice of the clockmaker's apprentice, so 
help feels like part of the story and not a pop-up from outside the game.
Feature 2: Recommendation Engine UI ("Next Step" cards)
• Simulated AI concept: a rule-based recommender that explains its suggestions. Each room has a 
side panel recommending the player's next move.
The Clockmaker's Vault | CSC 4370/6370 | Page 5
• What a card shows: a confidence label (High, Medium or Low) and a one-line reason, such as 
"You've found 2 of 3 clues here. The Archive probably has the last one."
• How it is built: the cards are static HTML styled to match the rest of the game.
• Original design decision: the confidence label is a brass-style tag that shows a text word and an 
icon, so it never depends on color alone.
How the two features complement the track
The Apprentice helps a stuck player move forward without handing over the answer, and the Next Step 
cards keep three rooms from feeling like a maze. Together they make the escape room friendlier for 
first-time players while keeping the puzzle itself intact.
Checks we will record for both features

• Keyboard access: every card can be reached and used with the keyboard, in a sensible focus 
order.
• Color contrast: checked on the confidence labels and badges.
7. User Experience
Use cases by page
• Home: a new visitor gets the story and the goal in a few seconds and starts playing.
• Puzzle Rooms: the player works through one room at a time, uncovers clues, and gets a hint when
stuck.
• Clue Board: the player looks over every clue found so far and can filter down to the key ones.
• Final Unlock: the player tries a code and finds out right away whether it worked.
• Team: visitors and graders can see who built which part.
Accessibility notes
• Every page uses semantic landmarks (header, nav, main, section, footer), with one h1 and 
headings in logical order.
• A skip link jumps to the main content, and every link, button, tab and card gets a visible :focus￾visible style.
• Body text meets WCAG AA contrast (4.5:1). Clue states pair an icon with a text label, so color is 
never the only signal.
• The radio buttons and checkboxes behind the tabs and filters have proper labels and work from 
the keyboard. We will hide them visually without removing them from the page, so screen readers
and keyboards still find them.
• Every animation respects prefers-reduced-motion, and all images have alt text.
Responsive plan
We are designing mobile first, with breakpoints at 600px and 1024px. Under 600px, content stacks in a 
single column, room tabs scroll sideways, and the next-step panel drops below the room. From 600px to

1024px, the clue board switches to two columns. Past 1024px, the full Grid layouts from the wireframes 
take over.
Visual style
Adithya will define the color palette, type scale and spacing as CSS custom properties, so the whole 
game shares one look. The mood is an old clockmaker's workshop, with warm metal tones, dark 
backgrounds and strong contrast. Fonts are Cinzel for headings and Inter for body text. Color is never 
the only way we show something, because every state also has a text label or an icon.

Risks and how we will handle them
• The four-dial code check is complex. The selector chain gets long and easy to break. We will build 
it first, keep it in its own clearly commented block, and test it with every digit before moving on.
• Newer CSS may not work everywhere. We will avoid depending on :has() and similar newer 
selectors, and stick to sibling combinators that every major browser supports. Test T8 will confirm 
this.
• Motion can hurt usability. Every animation has a reduced-motion fallback, and none runs longer 
than it needs to.
• Teammates may fall behind. Daily standups and the Kanban board make blockers visible early, 
and anyone who finishes a card can help with the next one in the Review column.

Inside style.css, the design tokens come first as custom properties on :root (colors, type sizes, spacing, 
timing). Every later rule reads from those tokens, so changing the whole look means editing a few lines 
at the top. We chose one stylesheet over several because the site is small, and it keeps the walkthrough 
in VS Code simple: one HTML file, one CSS file, and the story of how they connect. We will use class 
names that describe purpose, such as .clue-card or .room-tab, instead of names that describe looks.
